# Leather Catalogue

Customer-facing leather catalogue website.

## Architecture

```
Streamlit
    ↓
Supabase Database
    ↓
Supabase Storage
```

## Features

- Leather catalogue
- Leather specifications
- Main leather images
- Close-up/grain images
- Search
- Filtering
- Customer enquiries

## Setup

1. Copy `.streamlit/secrets.toml.example` to `.streamlit/secrets.toml`.
2. Fill in your Supabase Project URL and publishable key.
3. Never commit `.streamlit/secrets.toml` to GitHub — it is already in `.gitignore`.
4. Install dependencies: `pip install -r requirements.txt`
5. Run locally: `streamlit run app.py`
   (or push to GitHub and deploy on Streamlit Community Cloud, which needs no local Python install)

## Database

Leather information is stored in Supabase PostgreSQL, table `leather_products`.

```sql
create table public.leather_products (
    id bigint generated by default as identity primary key,

    leather_id text unique not null,
    article_name text not null,

    color text,
    thickness text,
    tannage text,
    animal text,
    origin text,

    main_photo text,
    closeup_photo text,

    description text,

    is_active boolean default true,

    created_at timestamp with time zone default now(),
    updated_at timestamp with time zone default now()
);

alter table public.leather_products
enable row level security;

create policy "Public can view active leather products"
on public.leather_products
for select
to anon
using (is_active = true);
```

## Images

Leather photographs are stored in Supabase Storage, in a single bucket (e.g. `leather-images`), with no per-ID subfolders:

```
leather-images/
    Cow Lionel.JPG
    Cow Lionel Grain.JPG
```

The database stores just the filename in `main_photo` / `closeup_photo`; the app builds the public URL from the bucket + filename.

## Security

- Supabase credentials are stored using Streamlit secrets, never hardcoded.
- The public catalogue uses the Supabase **publishable** key only, with Row Level Security enabled (read-only, active products).
- Never use the `sb_secret_...` key or the database password in this app.
